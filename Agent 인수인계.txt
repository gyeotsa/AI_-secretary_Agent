## 2026-07-27 웹 검색 답변 길이와 출처 표시 간소화

- 검색 요약 LLM이 URL을 답변 본문에 직접 복사하지 않으면 기존 안전장치가 요약을 폐기하고 검색 결과 5건의 제목·URL·스니펫 전체를 사용자와 TTS에 노출했다. 단순히 제품명을 물은 질문에 지나치게 긴 답변이 나온 직접 원인이다.
- 검색 근거 검증은 Tool 단계의 구조화 결과·실제 HTTP(S) URL 검사로 유지한다. 요약 LLM에는 이름·정답 질문은 한 문장, 상세·비교 요청도 최대 세 문장으로 제한한다.
- 출처 URL 삽입은 LLM에게 맡기지 않고 Browser Plugin이 상위 결과 최대 2개를 `출처:` 한 줄로 자동 첨부한다. 요약 실패 시에도 원문 결과 전체를 덤프하지 않고 “결과를 요약하지 못했습니다”만 표시한다.
- TTS는 기존 `출처:` 제거 규칙으로 핵심 답변만 읽고 URL은 읽지 않는다.
- 실제 일반 사용자 권한 E2E에서 `캘러웨이 신형 드라이버는 뭐야?`에 한 문장 핵심 답변과 공식 Callaway URL을 포함한 출처 2개만 반환하는 것을 확인했다.

## 2026-07-27 최신 정보 실제 웹 검색 및 출처 검증 연결

- 첨부 로그의 타이틀리스트·테일러메이드 질문에는 Tool 실행 로그가 전혀 없고 `RAG context: []`도 비어 있었다. `MPH 140`, `TSi3`, `M5.5` 답변은 검색이나 RAG가 아니라 로컬 LLM 학습 기억의 환각이었다.
- Browser Plugin에 `web.search` Intent와 `browser_web_search` Tool을 추가했다. 최신·신형·최근·출시·특정 연도·검색/찾기/확인 요청은 일반 대화로 보내지 않고 실제 웹 검색을 실행한다.
- 구형 `duckduckgo-search`가 Windows 인증서 저장소 오류와 패키지 이전 경고를 발생시켜 후속 패키지 `ddgs 9.14.4`를 설치하고 requirements를 `ddgs>=9,<10`으로 변경했다. 앱과 같은 사용자 권한의 실제 검색에서 Titleist Newsroom을 포함한 결과와 URL 반환을 확인했다.
- 검색은 원 질문과 `official 공식` 보강 질문을 함께 실행해 중복 URL을 제거한다. 공식·Newsroom·Media Center 결과를 우선하고 TikTok·Pinterest·Facebook·Instagram·포럼 계열은 감점한다.
- `26년` 같은 두 자리 연도는 현재 세기의 `2026년`으로 정규화한다. 후속 “응 어떤 제품?”, “그럼 다른 제조사는?”는 최근 web.search query와 결합해 주제를 잃지 않는다.
- Verifier는 결과가 비어 있거나 HTTP(S) 출처 URL이 없으면 실패 처리한다. 검색 결과 요약 LLM에는 검색 스니펫 밖의 제품명·연도를 추측하지 못하게 하고, 실제 URL을 답변에 인용하지 않으면 사용자 답변을 차단한다.
- 출처 URL은 UI 텍스트에는 표시하지만 TTS 정규화 단계에서 제거해 긴 URL을 음성으로 읽지 않는다.
- 실제 네트워크 검색은 샌드박스 내부에서는 Windows 인증서 저장소 접근 제한으로 실패했으나 앱과 동일한 사용자 권한에서는 성공했다. 배포 실행도 일반 사용자 권한이므로 같은 경로를 사용한다.

- 코딩 역할 프롬프트를 시니어 소프트웨어 엔지니어 기준으로 보강했다. 실행 가능성·정확성·유지보수성·기존 동작 보존을 요구하되 단순 작업에는 불필요한 추상화와 상용구를 만들지 않는다.
- Python의 `print("안녕")` 한 줄은 문법적으로도 실행상으로도 완전한 프로그램이다. 실제 `.venv` Python으로 대상 파일을 실행해 표준 출력 `안녕`과 종료 코드 0을 확인했다. 코드 줄 수가 아니라 요구 충족·실행·검증 여부를 품질 기준으로 삼는다.
- 사용자 지시의 따옴표 리터럴이 생성 결과에 실제 포함되는지 저장 전에 검사한다. 예를 들어 `"안녕"` 요청에 다른 문자열을 만든 경우 원본 파일을 보존하고 실패 처리한다.

## 2026-07-27 파일 생성과 내용 수정 Intent 분리

- 첨부 로그에서 프로젝트·파일 생성 자체는 실제 검증되었지만, `해당 파일에 코딩`과 `test.py 파일을 수정` 요청이 `filesystem.create_file`로 오분류되어 빈 내용으로 기존 파일을 다시 생성하는 흐름이 확인됐다.
- Filesystem Plugin에 `filesystem.write_file` Intent와 Tool을 별도로 추가했다. `코드`, `소스코드`, `코딩`, `수정`, `작성` 문맥은 새 파일 생성이 아니라 기존 파일 내용 작성으로 라우팅한다.

- 코드 작성은 코드 역할 전용 LLM에 기존 파일 내용과 사용자 지시를 전달하고, 설명·Markdown 펜스를 제거한 완성 파일 원문만 저장한다. 빈 응답이나 오류 응답이면 기존 파일을 덮어쓰지 않는다.
- 새 파일 생성은 배타적 생성 모드(`x`)를 사용해 같은 이름의 기존 파일을 절대 빈 내용으로 덮어쓰지 않는다.
- 프로젝트 이름 질문에 `test`처럼 이름만 답해도 Slot으로 받아들이도록 후속 답변 파싱을 보완했다.
- 생성·수정 완료 안내에서는 긴 Windows 절대 경로를 읽지 않고 파일명·폴더명만 표시한다. 실제 절대 경로와 검증 결과는 디버그 로그에 남는다.
- 최근 파일 문맥→코드 모델 결과 저장, 기존 파일 생성 충돌 시 원본 보존, 이름만 제공한 후속 답변을 자동 테스트로 검증했다.

## 2026-07-27 Workspace 실제 프로젝트·파일 생성 연결

- 첨부 로그의 `launch_monitor 프로젝트가 생성되었습니다`와 `launch_monitor.py가 생성되었습니다`에는 Tool 호출·Verifier 로그가 없었다. Registry가 해당 실행 intent를 제공하지 않아 일반 대화 LLM이 성공 문장만 생성한 것이 원인이었다.
- Filesystem Plugin에 범용 `filesystem.create_project`와 `filesystem.create_file` Intent/Slot 계약을 추가했다. 프로젝트명이나 확장자를 포함한 파일명이 없으면 추측해서 성공 처리하지 않고 사용자에게 필요한 이름을 질문한다.
- 상단에서 명시적으로 선택한 Workspace를 생성 루트로 사용한다. 경로 정규화 후 Workspace 외부로 벗어나는 이름은 차단하며, 프로젝트 생성이 성공하면 이어지는 파일 작업이 프로젝트 내부에서 실행되도록 새 폴더를 현재 Workspace로 전환한다.
- 생성 도구는 JSON으로 실제 절대 경로를 반환하고 `ToolVerifier`가 해당 디렉터리 또는 파일이 디스크에 존재하는지 확인한 경우에만 성공 문장을 표시한다.
- 도구 실행으로 Workspace가 변경되면 응답 시 UI의 폴더명·경로도 새 Workspace로 갱신한다.
- `get_workspace_info()`가 설정 여부를 반대로 판단하던 조건문 오류를 수정했다.
- 프로젝트명 질문→후속 답변→실제 폴더 생성, 파일명 질문→후속 답변→실제 파일 생성 및 존재 검증 테스트를 추가했다.

## 2026-07-27 내부 작업 ID 숨김 및 실제 알람 실행 연결

- Executor가 확인 질문 뒤에 붙이는 `대기 작업 ID: ...`는 내부 추적 정보이므로 일반 UI와 TTS 응답에서는 `ResponsePresenter`가 제거한다. 원본 Executor 응답은 디버그 로그에 유지되어 문제 추적에는 영향이 없다.
- TTS 영문 정규화는 특정 문구 치환이 아니라 약어 규칙을 사용한다. `ID`는 `아이디`, 발음 사전에 있는 `GAME`은 `게임`, 사전에 없는 `API`와 `GPU`는 각각 `에이피아이`, `지피유`로 읽는다.
- 기존 “3분 뒤 알람”은 일반 대화 모델이 완료 문장만 생성했고 실제 예약 도구가 호출되지 않았으며, `AutomationEngine`도 앱 시작 시 가동되지 않아 알람이 울리지 않았다.
- Plugin Registry에 `alarm` 플러그인과 선언형 `alarm.set_relative` intent를 추가했다. 시간 단위를 초로 정규화해 `AutomationEngine.add_alarm()`을 호출하며 특정 3분 문장에 종속되지 않는다.
- 단발 알람은 절대 실행 시각과 `action_type=alarm`을 DB에 저장하고, 엔진 재시작 후에도 다시 적재한다. 실행 후 자동 비활성화되며 LLM을 거치지 않고 UI 알림과 TTS를 직접 발생시킨다.
- 앱 시작 시 AutomationEngine을 가동한다. 자동화 알림에는 작업 ID를 노출하지 않고, 실제 음성 실행기가 있는 경우에만 백그라운드 TTS를 시작하도록 방어했다.
- 1초 단발 알람의 실제 콜백 발생, 3분 요청의 180초 변환, 내부 ID 비노출, 약어 발음을 자동 테스트로 검증했다.

## 2026-07-15 후속 수정

- **[Fix] 원형 사운드바 참조 오류 수정**: 원형 사운드바가 `paintEvent`에서 직접 렌더링되는 구조에 맞춰, 제거된 `circular_sound_bar` 위젯 참조를 상태 변수와 렌더링 갱신으로 교체했습니다. 텍스트 입력, 사운드바 API, 창 모드 전환 스모크 테스트를 통과했습니다.

- `hello를 읽어봐`가 일반 대화 모델로 전달돼 `[GAME]하로`를 생성한 문제를 해결했다. system_tools 플러그인에 `repeat_text` 도구와 `speech.repeat_text` intent를 선언해 사용자가 지정한 문자열을 LLM 변형 없이 그대로 화면에 반환하고, TTS 발음 계층에서만 변환한다.
- TTS가 성공했더라도 읽은 본문에 `오류:`라는 단어가 있으면 실패로 기록하던 로그 판정을 `TTS 오류:` 접두어 검사로 좁혔다.
- 실제 Executor에서 지역 없는 날씨 질문이 확인 질문으로 전환되고 `hello를 읽어봐`가 정확히 `hello`를 반환하는 것을 검증했다. 전체 테스트 결과는 `119 passed, 4 deselected`다.
