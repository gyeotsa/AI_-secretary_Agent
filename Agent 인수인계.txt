## 2026-08-08 Obsidian Knowledge Vault 연결

- Obsidian을 단순 뷰어로 사용하고 아니스가 Markdown Vault의 분류·원자 노트·Wikilink·RAG 동기화를 관리하는 `core/obsidian_vault.py`와 `obsidian` Plugin을 추가했다.
- 모든 대화는 감사·재컴파일용 `raw/conversations`에 보관하지만 기본 RAG에서 제외한다. 명시적 기억, 선호, 설정, 프로젝트 결정만 `wiki/`에 승격되고, 일반 질문·명령·잡담은 정규화한 패턴이 3회 이상 반복될 때만 활성 지식이 된다.
- 각 기억은 중요도, 신뢰도, epistemic status, action, topic, source, workspace를 frontmatter로 보유한다. 주제와 action Map of Content를 만들고 `obsidian_explore`가 최대 깊이 3의 BFS로 Wikilink를 실제 탐색한다.
- `obsidian_sync_to_rag`는 wiki만 하이브리드 RAG에 넣고, `obsidian_lint`는 깨진 링크·고아·얇은·중복 페이지를 점검한다. 민감정보는 Vault 자동 저장에서도 차단한다.
- 기본 Vault는 `data/AnisKnowledgeVault`이고 설치된 Obsidian 앱은 URI로 열 수 있다. 다른 Vault는 Plugin 설정 Tool 또는 `OBSIDIAN_VAULT_PATH`로 연결한다.

## 2026-08-08 Post-training 기반 선행 Runtime 개선

- Post-training을 바로 실행하지 않고 실행 trajectory와 사용자 피드백을 먼저 축적하도록 `core/learning_runtime.py`를 추가했다. 민감정보를 마스킹하고 라우팅·Tool 요청·결과·최종 상태를 하나의 실행 ID로 연결한다.
- Plugin Registry 메타데이터에서 요청별 Tool Loadout을 만들며, 일반 대화에는 Tool 스키마를 싣지 않고 명확한 Intent에는 해당 Tool만 노출한다. ReasoningPolicy는 단순 대화·단일 Tool·복합·위험 작업의 추론 수준을 분리한다.
- RAG는 벡터/어휘 후보를 독립 검색해 RRF로 합치고 선택적 Cross-Encoder 재정렬과 retrieval confidence를 제공한다. 신뢰도가 낮은 후보는 Context에서 사실 근거로 사용하지 않는다.
- 대용량 Tool 결과 offload, 최근 대화 예산, 작업 checkpoint를 위한 `core/context_lifecycle.py`를 추가했다. 외부 콘텐츠의 ANSI 제어문자와 명령형 prompt injection 격리도 공통 SafetyLayer에 추가했다.
- 결정론적 애플리케이션 평가, 격리된 Skill 개선 후보, SFT/DPO/Verifier-RL JSONL 내보내기를 구현했다. 학습과 배포는 자동 실행하지 않으며 사람 검토와 95% 회귀 게이트를 요구한다.
- `POST_TRAINING.md`, `training/post_training_config.json`, `test_post_training_runtime.py`에 운영 원칙과 검증을 기록했다.
- 구현 커밋: `bc24b36` (`에이전트 평가와 학습 준비 런타임 구축`). 전체 회귀 테스트는 `371 passed, 4 deselected`를 통과했다.
- 다음 해야 할 일: 실제 사용자 피드백 UI를 연결하고 충분한 승인 데이터가 쌓인 뒤 역할별 QLoRA 파일럿을 별도 브랜치에서 실행한다.

- 첨부 로그의 `launch_monitor 프로젝트가 생성되었습니다`와 `launch_monitor.py가 생성되었습니다`에는 Tool 호출·Verifier 로그가 없었다. Registry가 해당 실행 intent를 제공하지 않아 일반 대화 LLM이 성공 문장만 생성한 것이 원인이었다.
- Filesystem Plugin에 범용 `filesystem.create_project`와 `filesystem.create_file` Intent/Slot 계약을 추가했다. 프로젝트명이나 확장자를 포함한 파일명이 없으면 추측해서 성공 처리하지 않고 사용자에게 필요한 이름을 질문한다.
- 상단에서 명시적으로 선택한 Workspace를 생성 루트로 사용한다. 경로 정규화 후 Workspace 외부로 벗어나는 이름은 차단하며, 프로젝트 생성이 성공하면 이어지는 파일 작업이 프로젝트 내부에서 실행되도록 새 폴더를 현재 Workspace로 전환한다.
- 생성 도구는 JSON으로 실제 절대 경로를 반환하고 `ToolVerifier`가 해당 디렉터리 또는 파일이 디스크에 존재하는지 확인한 경우에만 성공 문장을 표시한다.
- 도구 실행으로 Workspace가 변경되면 응답 시 UI의 폴더명·경로도 새 Workspace로 갱신한다.
- `get_workspace_info()`가 설정 여부를 반대로 판단하던 조건문 오류를 수정했다.
- 프로젝트명 질문→후속 답변→실제 폴더 생성, 파일명 질문→후속 답변→실제 파일 생성 및 존재 검증 테스트를 추가했다.

## 2026-07-27 내부 작업 ID 숨김 및 실제 알람 실행 연결

- Executor가 확인 질문 뒤에 붙이는 `대기 작업 ID: ...`는 내부 추적 정보이므로 일반 UI와 TTS 응답에서는 `ResponsePresenter`가 제거한다. 원본 Executor 응답은 디버그 로그에 유지되어 문제 추적에는 영향이 없다.
- TTS 영문 정규화는 특정 문구 치환이 아니라 약어 규칙을 사용한다. `ID`는 `아이디`, 발음 사전에 있는 `GAME`은 `게임`, 사전에 없는 `API`와 `GPU`는 각각 `에이피아이`, `지피유`로 읽는다.
- 기존 “3분 뒤 알람”은 일반 대화 모델이 완료 문장만 생성했고 실제 예약 도구가 호출되지 않았으며, `AutomationEngine`도 앱 시작 시 가동되지 않아 알람이 울리지 않았다.
- Plugin Registry에 `alarm` 플러그인과 선언형 `alarm.set_relative` intent를 추가했다. 시간 단위를 초로 정규화해 `AutomationEngine.add_alarm()`을 호출하며 특정 3분 문장에 종속되지 않는다.
- 단발 알람은 절대 실행 시각과 `action_type=alarm`을 DB에 저장하고, 엔진 재시작 후에도 다시 적재한다. 실행 후 자동 비활성화되며 LLM을 거치지 않고 UI 알림과 TTS를 직접 발생시킨다.
- 앱 시작 시 AutomationEngine을 가동한다. 자동화 알림에는 작업 ID를 노출하지 않고, 실제 음성 실행기가 있는 경우에만 백그라운드 TTS를 시작하도록 방어했다.
- 1초 단발 알람의 실제 콜백 발생, 3분 요청의 180초 변환, 내부 ID 비노출, 약어 발음을 자동 테스트로 검증했다.

## 2026-07-15 후속 수정

- **[Fix] 원형 사운드바 참조 오류 수정**: 원형 사운드바가 `paintEvent`에서 직접 렌더링되는 구조에 맞춰, 제거된 `circular_sound_bar` 위젯 참조를 상태 변수와 렌더링 갱신으로 교체했습니다. 텍스트 입력, 사운드바 API, 창 모드 전환 스모크 테스트를 통과했습니다.

## 2026-08-03 웹 학습 검색 품질·한국어 말투 자연스러움 개선

- 사용자 로그의 첫 요청은 검색 결과 0건이 아니었다. Tool은 약 70초 동안 실행된 뒤 학습 품질 검증에서 실패했지만 Executor가 모든 live/source 실패를 `실시간 출처를 확인하지 못함`으로 바꿔 원인을 잘못 안내했다. 웹 학습은 이제 `검색은 완료됐지만 말투 학습 품질 검증에 실패`와 실제 실패 이유를 표시하며, 일반 실시간 검색 실패와 구분한다.
- `...라는 게임에서 나오는...`뿐 아니라 `...라는 게임에 등장하는 '...'라는 캐릭터` 표현도 동일한 `(게임, 캐릭터)` 구조로 추출한다. 사용자 문장을 그대로 검색어로 쓰지 않고 `게임명 캐릭터명 캐릭터 성격 대사 말투 공식 자료` 형태의 안정적인 검색 대상으로 정규화한다.
- 학습 검색은 일반 검색어 외에 정확한 게임·캐릭터명과 `대사·대화`, `성격·말투`를 조합한 검색식을 추가한다. 후보 제목·snippet에서 캐릭터명, 게임명, 대화 특성을 점수화하고 육성·티어·스킬 공략은 감점해 실제 방문 순서를 정한다.

- `read_note()`는 Vault 밖 경로를 거부하며 `open_note()`도 실제 Vault 문서만 연다. 그래프 API·라우팅·UI 집중 테스트는 `14 passed`; 실제 오프스크린 창 생성도 `graph_ui_ok`로 확인했다.
