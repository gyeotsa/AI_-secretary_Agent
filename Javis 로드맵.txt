# Jarvis 개인 AI OS 개발 로드맵

> Jarvis가 내 PC를 이해하고, 내 일을 대신하는 개인 AI OS로 만들기 위한 단계별 로드맵

> 2026-07-27 상태 정정: 아래 12 STEP의 `완료`는 당시 파일·클래스 구현 여부를
> 기록한 역사적 표기입니다. 최근 실제 사용 검토에서 Planner/Executor/Reflection/
> Multi-Agent/Project Indexer/Observer가 존재하더라도 Codex 수준의 폐쇄 실행 루프와
> 장시간 E2E가 완성된 것은 아님을 확인했습니다. 현행 우선순위와 수락 기준은
> `AGENT_RUNTIME_ROADMAP.md`를 단일 진실 공급원으로 사용합니다.

## 2026-07-27 현행 우선순위

1. 모든 Tool 결과를 타입과 증거로 표현하고 허위 완료를 구조적으로 차단
2. 대화·pending request·Intent Slot·Artifact를 하나의 Task State로 통합
3. 키워드 중심 라우터를 의미 기반 Capability Router로 발전
4. 저장소 분석→patch→lint/test→diff 검토를 수행하는 Coding Agent 구축
5. Workspace 자동 복원·증분 인덱싱·프로젝트별 Memory/RAG 연결
6. Planner·Executor·Verifier·Recovery를 분리한 재계획 가능 Orchestrator 구축

완료 판정은 코드 존재가 아니라 자동 회귀 테스트와 실제 종단 실행을 모두 통과한
경우에만 사용합니다.

## Jarvis 5단계 진화 로드맵 (최종 비전)

### Level 1: AI Assistant (현재 단계)
**특징**: 질문 → LLM → Tool → 답변
- ChatGPT에 Tool을 붙인 수준
- 예: "엑셀 만들어." → 엑셀 생성 → 끝

---

### Level 2: Agent OS (기반 완료, 세부 보완 필요)
**특징**: Planner → Executor → Reflection → Memory → Permission → Plugin → Observer
- 여기까지가 위 12 STEP 로드맵
- Jarvis가 코딩, 문서 작업, 브라우저, Git, Windows 제어를 꽤 잘 함
- **하지만 아직 명령을 기다림**

---

### Level 3: Proactive Jarvis (진짜 재미있는 단계)
**특징**: Jarvis가 먼저 말함!
- Event를 감지하고 먼저 행동
- 예:
  - "보스, 오늘 Commit 안 했습니다."
  - "보스, 회의까지 15분 남았습니다."
  - "보스, Downloads에 계약서가 생겨 자동으로 정리했습니다."
- **필요한 것**: Goal Manager
  - 현재 목표 기억 (예: Jarvis 개발 → Git 유지 → 메일 확인 → 운동)

---

### Level 4: Digital Twin
**특징**: 사용자를 모델링
- Jarvis가 사용자의 패턴을 앎
- 예:
  - 보스는 아침에는 코딩, 오후에는 문서, 밤에는 게임
  - 회의자료는 항상 PPT → 다운로드 → Teams
  - Python 프로젝트는 항상 VSCode
- **기반**: Knowledge Graph
- 결과: "평소처럼 해." 라고만 말해도 Jarvis가 무슨 뜻인지 앎

---

### Level 5: Cognitive Architecture (거의 AGI 연구 수준)
**특징**: Jarvis 안에 여러 개의 "뇌"가 있음
- 전문 Agent들: Planner, Critic, Researcher, Coder, Vision, Memory, Scheduler, Browser, Office
- Planner가 작업을 적절한 Agent에게 분배
- **Meta Learning**: 자기 자신을 개선
  - Task 실패 → 왜 실패? → Prompt 수정 → Tool 선택 변경 → Memory 업데이트 → 다음부터 개선
- 이게 Claude Code도 많이 사용하는 방식

---

### 최종 비전: Personal AI Operating System
**개념**: Windows 자체가 Jarvis 중심으로 동작
- Windows 위에 AI 하나가 있는 것이 아니라, Windows 자체가 Jarvis 중심
- 구조:
  ```
  Windows → Jarvis Kernel → Permission → Plugin → Knowledge → Memory → Automation → Applications
  ```
- 사용자는 프로그램을 실행하지 않음
- 그냥 "Jarvis, 이번 프로젝트 계속하자." 한마디면 됨
- Jarvis가 전부 준비:
  - VSCode 실행
  - Git 상태 확인
  - 어제 작업 복원
  - 관련 문서 열기
  - 필요한 터미널 실행

---

### 진정한 최종 목표: AI 동료
**개념**: 단순한 데스크톱 비서가 아니라, 사용자의 디지털 업무 전반을 담당하는 개인 AI 플랫폼
- 장기 목표를 기억
- 작업을 며칠 또는 몇 주에 걸쳐 이어서 진행
- 새로운 도구를 스스로 학습해 사용
- 사용자의 피드백을 통해 행동 방식을 개선
- 필요할 때만 개입하고 평소에는 조용히 백그라운드에서 환경을 관리

**핵심 순환**:
```
Windows → Observer → Knowledge Engine → Planner → Action → Learning → Observer (계속 순환)
```

## 현재 상태 평가 (Level 2 - Agent OS)

**✅ Level 2 Agent Runtime 완료! 진정한 Jarvis 중앙 실행 엔진!**

현재 Executor가 완전히 재설계됐습니다! 더 이상 "Task Runner"가 아닌 진정한 Agent Runtime입니다!

### 새로 구현된 Executor 메서드:
- **initialize()**: 초기화
- **execute_goal()**: 메인 메서드
- **run_iteration()**: 한 번의 반복 실행 (핵심!)
- **build_context()**: 모든 Context 조립 (Conversation + Memory + Workspace + OS + Task + Scratchpad)
- **select_task()**: 다음 Task 선택
- **reason_next_action()**: 다음 Action Reasoning
- **select_tool()**: LLM 기반 Best Tool 선택 (Rule-based 아님!)
- **request_permission()**: Permission 체크
- **execute_tool()**: Tool 실행
- **verify_execution()**: 실행 결과 검증
- **process_observation()**: Observation 처리
- **reflect()**: Reflection
- **update_memory()**: Memory 업데이트
- **evaluate_goal()**: Goal 평가 (달성 여부 확인)
- **recover()**: 실패 복구 (Retry → Alternative → Fallback)
- **finalize()**: 최종 종료 처리
- **generate_response()**: 최종 답변 생성

### Level 2 완료!
이제 Jarvis는:
- Planner와 협력하고,
- Context를 조립하고,
- 적절한 Tool을 선택하고,
- 권한을 확인하고,
- 실행 결과를 검증하고,
- 실패를 복구하고,
- Memory와 Scratchpad를 갱신하며,
- 목표 달성 여부를 계속 판단합니다!
